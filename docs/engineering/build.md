# build

`/build` implements only the approved plan.

It is the coding step, but it remains constrained by the issue, acceptance criteria, `CONTEXT.md`, ADRs, and `DOD.md`.

## Use When

- The plan is approved.
- A branch or worktree is ready.
- The owner wants the scoped implementation completed.

## Output

A build summary with changed files, validation performed, problems found, and follow-up work.

## Important Rule

New work becomes a follow-up issue unless required to satisfy the current acceptance criteria.
