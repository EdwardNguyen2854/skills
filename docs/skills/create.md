# Create a product or change

`/create`

The main guide. It understands the request, checks the working state, routes clarification/planning, coordinates implementation and verification, and prepares delivery.

## Use when

- The owner describes a product, feature or change.
- A bug or polish request needs the full workflow.
- A read-only review/audit or planning-only request needs the correct read-only route.
- Work should be routed to planning, cleanup, security/UI/UX or review.

## Outcome

A working, verified result explained in plain language, with branch/PR/release state and limitations stated separately.

## Key safeguard

It plans and reviews before coding, preserves unfinished work, checks branch purpose, and never treats "go" as merge or publication permission. Review, diagnosis and planning requests do not silently become implementation.
