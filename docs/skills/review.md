# Review plans and code

`/review`

Reviews plans before implementation and actual code/PR revisions afterward for product fit, correctness, security, architecture and UI/UX risk.

## Use when

- Before approval of an implementation plan.
- Before opening or merging a PR.
- After material code changes or a changed PR head/base.

## Outcome

A revision-specific verdict: ready, awaiting checks, or blocked, with actionable findings and owner-facing impact.

## Key safeguard

It does not review summaries instead of diffs, inherit stale approval, hide optional suggestions as blockers, or fake a human approval.
