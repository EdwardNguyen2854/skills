# Plan and review before coding

`/plan`

Produces a right-sized implementation plan with observable outcomes, risks, task boundaries and verification, then reviews it before code.

## Use when

- A feature or change needs implementation.
- Scope or dependencies need decomposition.
- A plan revision needs review or approval.

## Outcome

A reviewed plan revision that is approved, awaiting approval or clearly blocked.

## Key safeguard

Small work gets a short plan, not an exemption. Material changes require a revised, re-reviewed plan and applicable approval.
